# Contributing to UX.SOL

Thanks for helping improve UX.SOL. Contributions should keep registry items
readable, installable, accessible, and honest about wallet and network state.

## Development setup

1. Install Node.js 24.19.0 and pnpm 10.
2. Run `pnpm install`.
3. Copy `.env.example` to `.env.local` and configure only the integrations you need.
4. Run `pnpm dev` when interactive verification is required.

## Sources of truth

- `registry.json` defines every registry item and its dependencies.
- `registry/uxdotsol/` contains authored registry source.
- `lib/docs/` contains documentation metadata and examples.
- `public/r/` is generated by `pnpm registry:build`; never edit it manually.
- Selected `app/api/` routes are shipped with registry items through `registry.json`.

## Making a change

1. Keep the change scoped to one concern.
2. Update registry source, manifest metadata, and documentation together.
3. Add or update focused tests.
4. Run `pnpm lint`, `pnpm typecheck`, and `pnpm test`.
5. Run `pnpm registry:build` when registry source or metadata changes.
6. Review generated `public/r/` changes before opening a pull request.

## Registry item checklist

- Declare every runtime dependency and environment variable in `registry.json`.
- Include every supporting component, hook, library, or API route required after installation.
- Preserve loading, empty, error, unknown, and recovery states.
- Keep provider credentials and privileged logic server-side.
- Require explicit wallet approval and use devnet for transaction examples.
- Preserve semantic controls, keyboard access, visible focus, and reduced motion.
- Never fabricate wallet, RPC, token-safety, payment, or transaction results.

## Pull requests

Explain the user-facing impact, include screenshots for visible changes, and note
which checks were run. Maintainers may request a smaller change when a pull
request mixes unrelated registry, site, and generated-output work.
